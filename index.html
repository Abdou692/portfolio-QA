Contexte

Présentation du projet ParaBank

ParaBank est une application bancaire de démonstration utilisée pour simuler des parcours utilisateurs réels : consultation de comptes, ouverture de compte, paiement de factures, consultation des transactions et gestion de la session utilisateur. L’objectif du projet était de vérifier la conformité fonctionnelle, la fiabilité des règles métier et la sécurité des parcours sensibles.

Domaine bancaire

Le projet couvre des fonctionnalités proches d’une application bancaire : soldes, paiements, transactions et accès aux informations de compte.

Objectif QA

Concevoir des tests pertinents, exécuter les scénarios, détecter les anomalies bloquantes et documenter les résultats dans une logique qualité.

Approche outillée

Utilisation de Jira/Xray pour le suivi des tests, Selenium et Python pour l’automatisation, Behave/Gherkin pour les scénarios BDD.

Modules couverts

Login / Authentification Accounts Overview Account Details Open New Account Bill Pay Transactions Logout / Sécurité

Méthode

Plan et stratégie de tests

La stratégie s’appuie sur une analyse des risques, une priorisation des parcours critiques et une combinaison de tests positifs, négatifs, limites et de non-régression.

Périmètre testé
  • Vérification de l’affichage des comptes et des colonnes Balance / Available Amount.
  • Contrôle de l’accès aux détails d’un compte depuis la liste des comptes.
  • Ouverture d’un nouveau compte avec respect du dépôt minimum attendu.
  • Paiement d’une facture avec données bénéficiaire et montant valide.
  • Tests négatifs sur les montants nuls, négatifs et les soldes insuffisants.
  • Contrôle de l’accès aux pages sensibles après déconnexion.
Risques prioritaires
  • Validation d’un paiement alors que le solde est insuffisant.
  • Acceptation d’un montant négatif ou égal à zéro.
  • Incohérence entre solde affiché, montant disponible et historique des transactions.
  • Création d’un compte sans respecter la règle du dépôt minimum.
  • Accès non autorisé à des pages après logout.
1. Analyse fonctionnelle

Identification des fonctionnalités principales, des règles métier et des dépendances entre les modules.

2. Conception des cas de test

Rédaction des cas de test avec prérequis, données de test, étapes, résultats attendus et priorité.

3. Exécution dans Jira/Xray

Exécution des tests, suivi des statuts, collecte des preuves et documentation des résultats.

4. Gestion des anomalies

Création de bugs structurés avec description, étapes de reproduction, résultat obtenu, résultat attendu et impact.

5. Automatisation

Automatisation des parcours critiques avec Selenium WebDriver, Python et Behave pour faciliter la non-régression.

Extrait de steps Python avec Behave et Selenium

Extrait représentatif : le fichier complet contient plusieurs steps. Cette sélection montre les validations principales : sélection d’un compte, remplissage dynamique via tableau Gherkin, contrôle des messages d’erreur et vérification de non-confirmation. 

# features/steps/cas_de_test_avances_steps.py

from behave import when, then
from selenium.webdriver.support.ui import Select
from selenium.webdriver.common.by import By
from features.steps.selectors import *
from features.steps.common_steps import *
import time


@when("il sélectionne un compte source avec solde insuffisant (< 100$)")
def step_select_low_balance_account(context):
    """Sélectionner un compte source avec solde inférieur à 100$."""
    try:
        select_element = Select(context.driver.find_element(*FROM_ACCOUNT_SELECT))
        options = select_element.options

        if len(options) > 1:
            select_element.select_by_index(len(options) - 1)
        else:
            select_element.select_by_index(0)

        time.sleep(0.5)
        print("✅ Compte avec solde insuffisant sélectionné")

    except Exception:
        select_element = Select(context.driver.find_element(*FROM_ACCOUNT_ID))
        select_element.select_by_index(0)
        print("✅ Compte sélectionné via FROM_ACCOUNT_ID")


@then("le nouveau compte ne doit pas être créé")
def step_verify_account_not_created(context):
    """Vérifier que le compte n'a pas été créé."""
    time.sleep(1)

    success_elements = context.driver.find_elements(
        By.XPATH,
        "//h1[contains(text(), 'Congratulations')] | //h1[contains(text(), 'Account Opened')]"
    )

    if success_elements and any(elem.is_displayed() for elem in success_elements):
        raise AssertionError(
            "Le compte a été créé alors qu'il ne devrait pas l'être"
        )

    print("✅ Le compte n'a pas été créé")


@when("il remplit le formulaire avec :")
def step_fill_payment_with_table(context):
    """Remplir le formulaire Bill Pay avec les données du tableau Gherkin."""
    row = context.table[0]

    wait_type(context, PAYEE_NAME, row.get("payee", "Test"))
    wait_type(context, ADDRESS, row.get("address", "123 St"))
    wait_type(context, CITY, row.get("city", "City"))
    wait_type(context, STATE, row.get("state", "ST"))
    wait_type(context, ZIP, row.get("zipCode", "00000"))
    wait_type(context, PHONE, row.get("phone", "000-000-0000"))
    wait_type(context, ACCOUNT_NUMBER, row.get("account", "123"))
    wait_type(context, VERIFY_ACCOUNT, row.get("verifyAccount", "123"))

    amount = row.get("amount", "").strip()

    if amount:
        wait_type(context, AMOUNT, amount)
        print(f"✅ Montant saisi : {amount}")
    else:
        print("ℹ️ Montant vide intentionnel")

    select_element = Select(context.driver.find_element(*FROM_ACCOUNT_ID))
    select_element.select_by_index(0)


@then('un message d\\'erreur doit s\\'afficher indiquant "{error_message}"')
def step_verify_error_message(context, error_message):
    """Vérifier la présence d'un message d'erreur selon le cas testé."""
    time.sleep(2)
    page_text = context.driver.page_source.lower()

    keywords = {
        "solde insuffisant": ["insufficient", "balance", "solde"],
        "montant invalide": ["invalid", "amount", "negative"],
        "montant obligatoire": ["required", "empty", "amount required"]
    }

    search_keywords = keywords.get(error_message.lower(), [error_message.lower()])

    assert any(keyword in page_text for keyword in search_keywords), \
        f"Message d'erreur non trouvé : {error_message}"

    print(f"✅ Message d'erreur vérifié : {error_message}")


@then("le paiement ne doit pas être confirmé")
def step_verify_payment_not_confirmed(context):
    """Vérifier que le paiement n'a pas été validé."""
    success_elements = context.driver.find_elements(
        By.XPATH,
        "//h1[contains(text(), 'Bill Payment Complete')]"
    )

    if success_elements and any(elem.is_displayed() for elem in success_elements):
        raise AssertionError(
            "Le paiement a été confirmé alors qu'il devait être refusé"
        )

    print("✅ Le paiement n'a pas été confirmé")
